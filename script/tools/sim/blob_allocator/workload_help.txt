Modes:
  4k-align (default): Round each request up to a multiple of 4 KiB.
  max-value-align: Reserve at least the historical maximum aligned request size.
    Successful allocations can increase this maximum. Releases do not decrease it.
  Run each mode separately. The CLI measures one mode per invocation.

Allocation and eviction:
  Start empty. Each step attempts one allocation with a sampled request size.
  Occupancy = 100 * reserved bytes / capacity. Reserved bytes include padding.
  After success at or above the maximum, pause allocations and evict live blocks.
  Select each block uniformly, without size or age weighting.
  Stop at or below the minimum, then resume allocations. Use no background thread.
  Defaults: minimum 80%, maximum 90%. Supply integers: 0 <= minimum < maximum <= 100.
  Whole blocks can cross either threshold. Complete eviction after the last attempt too.
  --steps counts allocation attempts, including failures. Evictions do not consume steps.
  --sample-every counts allocation attempts. Sample after any eviction for that attempt.
  Also sample before and after each eviction cycle.

Sizes and failures:
  Sample each request size from --block-sizes.
  Percentages specify probabilities of allocation attempts, not shares of bytes.
  Omitted percentages give equal probabilities. Supply all percentages or omit all.
  Explicit percentages must total 100%.
  Record capacity and fragmentation failures. Continue without retrying or forced eviction.
  Failed requests never become eviction candidates. Failures can repeat below the maximum.
  Invalid operations, including double frees, abort the measurement.
  --seed controls separate random generators for sizes and eviction targets.
  Eviction does not change the request-size sequence.

Metrics:
  Occupancy percent = 100 * reserved / capacity.
  Internal fragmentation percent = 100 * (reserved - requested) / reserved.
  External fragmentation percent = 100 * (free - largest free range) / free.
  Undefined fragmentation percentages appear as N/A.
