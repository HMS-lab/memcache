# 详细配置项说明

## ubsio.disk.path

### 配置含义与示例

`ubsio.disk.path` 用于指定 UBS IO 用作本地 SSD 缓存的设备路径。支持整盘块设备、已有分区或 loop 设备，loop盘需要在宿主机创建后映射到容器中使用；多个路径使用英文冒号（`:`）分隔，最多 **16** 条。<span style="color:red">**配置的设备必须由 UBS IO 独占，且不能存在挂载点。**</span> **留空表示无盘模式，仅使用 `ubsio.mem.size_in_gb` 配置的本地内存池，重启后缓存数据不持久化。**

```ini
# 同时配置整盘、分区和 loop 设备
ubsio.disk.path = /dev/nvmexn1:/dev/nvmexn2p1:/dev/loopX

# 无盘模式
ubsio.disk.path =
```

---

## ubsio.standalone.device_count

`ubsio.standalone.device_count` 表示参与本地缓存路径分配的 device 数量。**为简化表述，下文使用 `device_count` 代指该配置项。其值应与已启用 DRAM 的 local_service 进程数一致；这里“已启用 DRAM”是指 `ock.mmc.local_service.dram.size` 非 `0`。**

- `0`：兼容旧逻辑。每个 deviceId 按 `ubsio.disk.path` 的路径下标选择设备，例如 `deviceId = 1` 选择第 2 条路径。
- 大于 `0`：在 `ubsio.disk.path` 中配置目标整盘、已有分区或 loop 设备。

示例：

- 有 `4` 个已启用 DRAM 的 local_service 进程、使用两块目标盘时：

```ini
ubsio.disk.path = /dev/nvmexn1:/dev/nvmeyn1
ubsio.standalone.device_count = 4
```

- 只有 `1` 个已启用 DRAM 的 local_service 进程、使用一块目标盘时：

```ini
ubsio.disk.path = /dev/nvmexn1
ubsio.standalone.device_count = 1
```

---

## ubsio.mem.size_in_gb

`ubsio.mem.size_in_gb` 表示单个 UBSIO 进程可使用的本地内存池容量，单位为 GB。该值应根据 MemCache 的部署形态、节点可供 UBSIO 使用的剩余内存，以及已启用 DRAM 的 local_service 进程数计算。

这里“已启用 DRAM”是指 `ock.mmc.local_service.dram.size` 大于 `0`；“剩余内存”是指扣除系统预留、推理进程和 MemCache DRAM 池等占用后，可分配给 UBSIO 的节点内存。计算公式如下，结果向下取整：

```text
ubsio.mem.size_in_gb = min(3072, floor(节点可供 UBS IO 使用的剩余内存（GB） / 已启用 DRAM 的 local_service 进程数))
```

<span style="color:red">**`ubsio.mem.size_in_gb` 不得低于 `5GB`。如果单个 UBSIO 进程可分配的内存不足 `5GB`，应先释放节点内存或减少已启用 DRAM 的 local_service 进程数，再配置该参数。**</span>

例如，节点可供 UBSIO 使用的剩余内存为 `200GB`，共有 `4` 个 `ock.mmc.local_service.dram.size > 0` 的 local_service 进程，则计算出的单进程配置上限为 `50GB`。对于 SSD 场景，推荐显式配置为 `10GB`：

```ini
# floor(200 / 4) = 50，单进程配置上限为 50GB
ubsio.mem.size_in_gb = 10
```

对于 MemCache 分离部署场景，单进程建议配置为 `50` GB；其他场景建议配置为 `10` GB。仅在需要使用 L2.5 能力时考虑增大该值；配置值不得超过上述计算结果，同时需要调整 [`ubsio.wcache.evict_water_level`](#ubsiowcacheevict_water_level)。

---

## ubsio.wcache.evict_water_level

`ubsio.wcache.evict_water_level` 是 L2.5 写缓存的内存淘汰水位，取值范围为 `0` 到 `100`，**表示 L2.5 使用量达到其写缓存内存容量的多少百分比后开始淘汰**。

### 层级定义

- **L2.5**：UBS IO 的内存写缓存层，位于 MemCache DRAM（L2）与本地 SSD（L3）之间，用于在内存中缓存 UBS IO 数据。
- **L3**：UBS IO 的本地 SSD 缓存层，由 `ubsio.disk.path` 指定的本地 SSD 或分区提供容量。

### 配置建议

#### L2.5 场景

仅使用 L2.5，不启用 L3。数据保留在 UBS IO 内存写缓存中，达到淘汰水位后直接丢弃。建议设置为较高水位，例如 `85`：

```ini
ubsio.disk.path =
ubsio.wcache.evict_water_level = 85
```

#### L3 场景

以 L3 为主要缓存层，L2.5 仅作为写入过程中的临时流转层。将水位设置为 `0`，使写入 L2.5 的数据尽快淘汰到 L3：

```ini
ubsio.disk.path = /dev/nvmexn1p1:/dev/nvmexn1p2:/dev/nvmexn1p3:/dev/nvmexn1p4
ubsio.wcache.evict_water_level = 0
```

#### L2.5 + L3 场景

同时使用 L2.5 和 L3。将水位设置为大于 `0` 的值，使数据优先保留在 L2.5，达到水位后再淘汰到 L3。例如：

```ini
ubsio.disk.path = /dev/nvmexn1p1:/dev/nvmexn1p2:/dev/nvmexn1p3:/dev/nvmexn1p4
ubsio.wcache.evict_water_level = 85
```

L2.5 + L3 场景可根据可用内存、SSD 容量和期望的冷热数据比例调整水位；水位越高，数据越倾向于保留在 L2.5。

---

## ubsio.bdm.batch_read.standalone.use_scratch_pool

`ubsio.bdm.batch_read.standalone.use_scratch_pool` 控制 standalone BatchGet 经 BDM 读盘时是否先将数据读入 scratch pool，再复制到上层 buffer。配置为 `false` 时，BDM 直接写入上层 buffer。

A3 场景必须开启 scratch pool，不支持 BDM 直接写入上层 buffer；其他场景建议关闭 scratch pool，使 BDM 直接写入上层 buffer，可减少一次内存拷贝：

```ini
ubsio.bdm.batch_read.standalone.use_scratch_pool = false
```

# 其他

## 设备配置

将目标整盘、已有分区或 loop 设备的路径写入 `ubsio.disk.path`。

### 场景一：DRAM + 空闲本地SSD盘（推荐）

单节点有一块或多块 NVMe 盘时，可直接配置目标盘；也可以配置已有分区，但设备必须由 UBS IO 独占且不能存在挂载点。

#### 1. 确认设备状态

通过以下命令确认目标设备路径、类型和挂载状态：

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS

# 检查目标设备是否存在挂载点，以 /dev/nvme0n1 为例
lsblk /dev/nvme0n1
findmnt /dev/nvme0n1
```

<span style="color:red">**⚠️ 配置前请反复确认目标设备路径。配置的设备必须由 UBS IO 独占，且不能存在挂载点和已有的可用数据**</span>

#### 2. 典型场景

有 `4` 个已启用 DRAM 的 local_service 进程并使用两块目标盘时，配置如下：

```ini
ubsio.disk.path = /dev/nvme0n1:/dev/nvme1n1
ubsio.standalone.device_count = 4
```

使用已有分区时，配置对应路径：

```ini
ubsio.disk.path = /dev/nvme2n1p1
ubsio.standalone.device_count = 4
```

---

### 场景二：DRAM + 无本地空闲SSD盘 + SSD盘有剩余容量可用 （loop 设备方案）

无可用物理盘时，可用 `fallocate` 和 `losetup --find --show` 创建 loop 块设备模拟盘，由系统自动选择空闲 loop 设备，并开启 direct_io 直通模式。创建后将 loop 设备路径配置到 `ubsio.disk.path`。

> <span style="color:red">**⚠️ 创建 loop 设备前，请先确认当前 loop 设备占用情况；不要手动复用已被占用的 `/dev/loopN`，否则可能导致数据丢失。**</span>

```bash
# 创建并预分配 1TB 镜像文件，容量可按需调整
sudo fallocate -l 1T /data/ubsio_disk.img

# 创建 loop 设备并输出系统实际分配的设备路径
LOOP_DEV=$(sudo losetup --find --show --direct-io=on /data/ubsio_disk.img)
echo "${LOOP_DEV}"
# 示例输出：/dev/loop2
```

将实际输出的 loop 设备路径写入 `mmc-local.conf`：

```ini
ubsio.disk.path = /dev/loop2
ubsio.standalone.device_count = 4
```

---

### 场景三：DRAM + 远程存储 （loop 设备方案）

使用DRAM + 远程网络文件系统挂载（例如A800）场景时，可在远程存储挂载点路径下创建文件并配置为loop块设备模拟盘的方式，使用远程存储容量放置kvcache数据。为达到较高性能，远程存储网络带宽建议不低于200GE。
> <span style="color:red"><strong>⚠️ 创建 loop 设备前，请先确认当前 loop 设备占用情况；不要手动复用已被占用的 <code>/dev/loopN</code>，否则可能导致数据丢失。</strong></span><br>
> <span style="color:red"><strong>⚠️ 如果有多个 A2/A3/A5 机器共用一个 A800，需要创建多个文件，每个文件分别配置为不同机器上的 loop 盘；多个机器不能使用远程存储上的同一个文件。</strong></span>

假设A800在两个计算节点机器A，B 上挂载路径均为 /data/A800/。则创建2个1TB容量文件以及配置loop模拟盘方式为：

```bash
# 创建并预分配 1TB 镜像文件，容量可按需调整
truncate -s 1T /data/A800/disk0.img
truncate -s 1T /data/A800/disk1.img

# 创建 loop 设备并输出系统实际分配的设备路径，在A节点上执行。
LOOP_DEV=$(sudo losetup --find --show --direct-io=on /data/A800/disk0.img)
echo "${LOOP_DEV}"
# 示例输出：/dev/loop2

# 创建 loop 设备并输出系统实际分配的设备路径，在B节点上执行。
LOOP_DEV=$(sudo losetup --find --show --direct-io=on /data/A800/disk1.img)
echo "${LOOP_DEV}"
# 示例输出：/dev/loop3
```

```bash
# 将实际输出的 loop 设备路径写入 `mmc-local.conf`，A节点上配置文件。
ubsio.disk.path = /dev/loop2

# 将实际输出的 loop 设备路径写入 `mmc-local.conf`，B节点上配置文件。
ubsio.disk.path = /dev/loop3
```

---

### 取消 loop 设备

> <span style="color:red">**⚠️ 仅在确认不再需要 loop 模拟盘且相关服务已经停止时执行，卸载后缓存数据将丢失。**</span>

```bash
# 1. 查看当前 loop 设备及其关联文件
losetup -a

# 2. 卸载 loop 设备，替换为实际设备路径
sudo losetup -d /dev/loop2

# 3. 删除镜像文件（可选）
sudo rm -f /data/ubsio_disk.img
```

### 注意事项

| 事项 | 说明 |
| --- | --- |
| 设备独占 | UBS IO 独占配置的整盘、分区或 loop 设备，不可与其他服务共享 |
| 挂载限制 | 配置的设备不能存在挂载点 |
| 路径上限 | `ubsio.disk.path` 最多配置 16 条路径 |
| 动态加盘 | standalone 模式不支持运行时加盘 |
| 复用设备 | 不同 deviceId 会写入 BDM disk head，不匹配时将拒绝恢复 |
| 权限 | 进程需要对块设备具有读写权限，建议使用 root 用户运行 |
| 磁盘规格 | 配置的全部本地SSD盘总和随机读带宽建议不低于 7GB/s，远程存储网络带宽建议不低于200GE。压测方法见[磁盘带宽压测指南](https://gitcode.com/zhangjialee/ubs-io/wiki/%E7%A3%81%E7%9B%98%E5%B8%A6%E5%AE%BD%E5%8E%8B%E6%B5%8B%E6%8C%87%E5%8D%97.md) |
