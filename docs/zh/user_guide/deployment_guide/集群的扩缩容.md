# 集群扩缩容

> MemCache 支持在 `world_size` 上限范围内动态增加或减少节点，无需重启 MetaService。

---

## 基本概念

| 概念  | 说明  |
| --- | --- |
| **world_size** | 集群最大节点数上限，配置文件设定，运行中不可修改（默认 256，最大 1024） |
| **实际节点数** | ≤ world_size 的任意值，可在运行中变化 |
| **rank ID** | 每个节点在集群中的唯一编号，自动分配 |

```text
world_size = 32, 初始 4 节点:

在线:  R0  R1  R2  R3  R4  R5  ...  R31
状态:  ●   ●   ●   ●   ○   ○        ○
       └─── 已部署 ───┘  └─── 可随时动态加入 ──┘
```

---

## 扩容（Scale-out）

新节点启动时会自动发现集群并加入，不需要改动已有节点的配置。

**流程：**

```text
新节点 → 连接 ConfigStore → 自动分配 rank ID
      → 与其他节点建立 P2P 连接
      → 向 MetaService 注册本机内存资源
      → 集群感知新节点加入，可参与数据分配
```

**前置条件：** 当前在线节点数 < world_size

---

## 缩容（Scale-in）

### 优雅退出

节点退出前，上层业务应先排空本节点的缓存数据，再调用退出接口。

```text
1. 排空数据 — 逐个删除或等待自然淘汰该节点上的 KV 条目
   可通过 Remove(key) 或 BatchRemove 完成

2. 调用 Stop() — 通知集群退出
   当前节点 → BmUnregister → MetaService 清理元数据
   → 释放 P2P 连接 → 关闭退出
```

**为什么需要排空？** `Unmount` 会检查目标节点上是否还有已分配的 blob（`allocatedSize_ == 0`），有数据时拒绝退出。这是为了防止误操作导致数据意外丢失。

### 故障退出

节点进程崩溃或网络断开时，MetaService 检测到 TCP 连接断开，自动清理该节点的资源记录，数据直接丢弃。

```text
节点崩溃 → MetaService HandleLinkBroken
  → ClearResource → EraseIf 强制删除数据
  → 从全局分配器移除该节点
```

### 说明

- **优雅退出**：需排空数据，保证退出时集群状态干净
- **故障退出**：无需关心数据，KVCache 可重算，丢失的缓存条目会在后续请求中重新 Prefill 计算
- **当前限制**：没有一键排空脚本或 API，需要上层业务逐个 Remove key

## 配置建议

| 场景  | 建议  |
| --- | --- |
| 中小规模集群 | `world_size = 64`，按实际节点数部署，预留 20%~50% 余量 |
| 大规模集群 | `world_size = 256`（上限 1024），满足多数场景扩展需求 |
| LLM 推理场景 | `world_size` 按最大预期节点数配置，GVA 地址空间自动按此计算 |
| 容量配置 | `hbm/dram.szie` 每个节点需配置相等的值，满足底层地址线性计算 |

---

## 使用限制

| 限制  | 原因  |
| --- | --- |
| world_size 运行中不可修改 | GVA 地址空间按 world_size 预分配 |
| 数据不可恢复 | 节点退出后其上缓存数据丢失，KVCache 场景下后续请求会重新 Prefill 计算 |
| 缩容可能影响命中率 | 退出节点的缓存数据丢失，短期内可能导致命中率下降，热数据会在新节点上逐步重建 |
| 单节点容量上限 | DRAM 和 HBM 各自上限 1TB |

---

## 实现原理

集群扩缩容依赖于 ConfigStore 和 GroupEngine 两层协作。

**扩容：**

新节点在 ConfigStore 的共享 bitmap 中标记自己的 rank ID。所有在线节点通过 watch 机制感知到 bitmap 变化后，与新节点交换内存地址信息，建立 P2P 数据传输连接，最后向 MetaService 注册完成资源挂载。

```text
新节点 → bitmap 置位 → 通知在线节点
      → 交换地址 → 建立 P2P 连接
      → 注册到 MetaService → 集群感知新节点
```

**缩容：**

节点退出时清除 bitmap 中的 rank ID，在线节点同步删除 P2P 连接。MetaService 将该节点的内存从全局分配器中移除。

```text
退出节点 → bitmap 清除 → 通知在线节点
       → 断开 P2P → 从全局分配器移除
```

**关键依赖：**

| 组件  | 作用  |
| --- | --- |
| ConfigStore | bitmap 共享与 CAS 协调，watch 分发事件 |
| GroupEngine | 监听 ConfigStore 事件，触发 join/leave 回调 |
| MetaService GlobalAllocator | 管理节点内存资源的挂载与卸载 |
